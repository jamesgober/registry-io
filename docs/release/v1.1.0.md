# Release v1.1.0 — Hazard-protected storage, no runtime dependencies
**Date:** 2026-10-13
**Compare:** `v1.0.0...v1.1.0`

## Summary

`registry-io 1.1.0` replaces the `arc-swap`-based handler storage with
a crate-internal snapshot cell protected by hazard pointers, adds four
methods to `SyncRegistry`, and fixes a panic-isolation gap in the async
registry.

With default features the crate now has **zero runtime dependencies**.
The optional `futures-core` dependency behind the `async` feature is
unchanged.

**Additive only.** Every item frozen by
[`docs/STABILITY-1.0.md`](../../docs/STABILITY-1.0.md) keeps its
signature and semantics. Upgrading from 1.0.0 requires no code change.

## New API

All four are methods on `SyncRegistry<E>`.

### `unregister_and_wait(&self, id: HandlerId) -> bool`

`unregister` guarantees that `notify` calls *starting* after it returns
do not run the handler, but a `notify` already in progress on another
thread may still be inside it. `unregister_and_wait` closes that
window: it removes the handler, then blocks until no other thread is
still running it.

- Returns `true` once the handler is not running anywhere except,
  possibly, further up the calling thread's own stack (when called
  from inside a handler it does not wait for itself), and will never
  run again.
- Returns `false` immediately if `id` is not registered.
- Blocks: spins briefly, then yields, then sleeps with a backoff capped
  at 1 ms. A handler that never returns makes it never return. Do not
  call it from async code; use `unregister` there.
- Conservative: if other writes happen while it waits, it may also wait
  for readers of those newer retired handler lists.

Use it before tearing down anything a handler touches:

```rust
use std::sync::Arc;
use std::sync::atomic::{AtomicBool, Ordering};
use registry_io::SyncRegistry;

let registry: SyncRegistry<()> = SyncRegistry::new();
let resource_open = Arc::new(AtomicBool::new(true));
let r = Arc::clone(&resource_open);
let id = registry.register(move |_| assert!(r.load(Ordering::SeqCst)));

assert!(registry.unregister_and_wait(id));
// No thread can be inside the handler now; safe to close.
resource_open.store(false, Ordering::SeqCst);
registry.notify(&());
```

### `clear_and_wait(&self)`

The `clear` counterpart, with the same guarantee and blocking behavior.

### `register_once(self: &Arc<Self>, handler: F) -> HandlerId`

`F: FnOnce(&E) + Send + 'static`. The handler runs at most once, even
under concurrent `notify` calls (exactly one caller runs it), then
unregisters itself. It is also unregistered when it panics. It holds
only a `Weak` to the registry, so it does not keep the registry alive.
Registers at the default priority `0`.

### `panic_count(&self) -> u64`

The number of handler panics caught by `notify` since the registry was
created, counted with or without an `on_panic` callback. Updated only
on the panic path, so it costs nothing while handlers behave.

## Changed

### Storage core

The handler list of both registries now lives in a crate-internal
`SnapCell<T>` (`src/snapshot.rs`) backed by a process-wide
hazard-pointer domain (`src/hazard.rs`).

- **Readers** (`notify`, `handler_count`, `contains`, ...) announce
  the current list pointer in a per-thread slot (one `SeqCst` store),
  validate it with one `SeqCst` load, borrow the list in place, and
  clear the slot (one release store). There is no reference-count
  traffic, no lock, and no allocation. If retired lists are pending,
  the reader makes a non-blocking attempt to free the ones nobody
  announces.
- **Writers** (`register*`, `unregister`, `clear`) serialize on a mutex
  that readers never touch, build the new `Vec`, swap it in, retire the
  old one, scan all announcements, and free every retired list that is
  not announced. Handler `Drop` code runs after the lock is released.
  Writers never wait for readers, so a handler that unregisters itself
  or another handler cannot deadlock.
- **Per-thread records.** Each dispatching thread owns one record of 8
  slots (one per level of nested dispatch), aligned to 128 bytes to
  avoid false sharing. Records sit in an append-only lock-free list,
  are never freed, and are reused after their thread exits. This list
  is the crate's only global state.
- **Fallback.** A thread with no free slot (dispatch nested more than
  8 deep, or thread-local storage already torn down) clones the `Arc`
  under the writer lock instead. Slower, still correct.
- `unregister` of an unknown id and `clear` of an empty registry swap
  nothing and allocate nothing.
- The panic callback is stored in a `std::sync::RwLock` (read only on
  the cold panic path).

See [`docs/ARCHITECTURE.md`](../../docs/ARCHITECTURE.md#storage-model)
for the design and the correctness argument.

### Async dispatch

Handler futures are polled in place. Each handler future used to be
boxed three times (handler wrapper, `CatchUnwind`, `JoinAll`) plus four
`Vec`s per `notify`: `3n + 4` allocations. Now concurrent `notify`
allocates `n + 1` for more than one handler, `n` for one handler, and
nothing for an empty registry. Panic reporting order is unchanged:
after all handlers finish, in priority order.

## Fixed

- **Async panic isolation at handler start.** A handler that panicked
  while building its future (the synchronous part of the closure,
  before returning the future) was called outside `catch_unwind`. The
  panic escaped `AsyncRegistry::notify` and `notify_sequential`,
  contrary to the documented guarantee. It is now isolated like a panic
  during `poll` and reported to `on_panic`. Regression test:
  `tests/async_start_panic.rs` (fails on 1.0.0, passes on 1.1.0).
- **Async-only builds.** Several tests and examples used the `sync`
  feature without declaring it, so `--no-default-features --features
  async` did not compile. They are now feature-gated.
- **`cargo deny check`.** `deny.toml` was missing, so the check
  rejected every license. Added.

## Removed

- The `arc-swap` dependency.
- The internal `JoinAll` combinator. It was never public.

## Performance notes

- **Why `pure_read` exists.** In `contention/notify` (and
  `notify/contended` in `sync_notify`) every handler increments an
  `AtomicU64` shared by all notifying threads. Those numbers mostly
  measure cache-line contention on that counter, and a faster registry
  can even look slower there because it reaches the counter more often.
  The new `pure_read` group runs the same sweep with handlers that do
  no shared writes, which isolates the registry's own read scaling:
  25% to 49% faster in every cell.
- **`contention/notify`** moved between -44% and +18% per cell; see
  `docs/PERFORMANCE.md` for the full table.
- **Writes at large handler counts.** `register` into 100 and 1000
  handlers is 7% and 12% slower. Writes are copy-on-write, and at large
  counts the cost is dominated by cloning every handler `Arc`, as in
  1.0. This is an accepted trade on the control-plane path for the
  faster read path. `unregister` is faster at every size.

## Upgrading

Change the version requirement to `registry-io = "1.1"`. No source
changes are needed. If you relied on `arc-swap` arriving transitively
through this crate, add it to your own `Cargo.toml`.
