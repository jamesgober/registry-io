# Release v1.2.0 - Review fixes

**Date:** 2026-11-11
**Compare:** `v1.1.0...v1.2.0`

## Summary

Fixes from an independent review. Additive only: every item frozen by
[`docs/STABILITY-1.0.md`](../../docs/STABILITY-1.0.md) keeps its
signature. MSRV unchanged (1.85). No runtime dependencies under any
feature set.

## Added

- `SyncRegistry::try_unregister_and_wait(id) -> WaitOutcome` and the
  `WaitOutcome` enum (`Waited`, `NotRegistered`, `WouldDeadlock`).
- Loom models of the hazard-pointer handshake, run in CI.

## Fixed

- `unregister_and_wait` from handlers on two threads at once no longer
  deadlocks both threads.
- A slow handler plus one `register` or `unregister` no longer makes
  every `notify` allocate and scan. With a pinned replaced list,
  `notify` went from 82 to 185 ns to 11 to 12 ns (Windows x86_64, 1
  handler); the steady state is unchanged.
- A panic payload, or a self-unregistered handler's captured state,
  whose `Drop` panics no longer escapes `notify`.
- Handler ids are unique across registries, so an id used on the wrong
  registry no longer removes an unrelated handler.

## Removed

- The unused optional `futures-core` dependency (`async` feature).

Every fix has a regression test.
